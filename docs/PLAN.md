# PLAN — build order, exit criteria, what not to do yet

Ordering principle: **put the risk that kills the project first and
cheapest.** That risk is not the stack. It is whether validated, recorded,
frequency-ordered isiXhosa content can actually be produced at the pace a
course needs. Everything below is ordered to answer that before anything
expensive is built.

Each phase has a small, visible exit criterion. Do not start the next phase to
escape a hard one.

## Phase 0 — Content spike (no app)

**Goal:** prove the content pipeline with hands, before code.

- Ingest isixhosa.click CSV into a scratch Postgres (`molo content ingest`
  can be a script here; the CLI proper comes in Phase 1).
- With a tutor (italki / UCT contact), hand-curate the **top 300** lexemes for
  Cape Town conversational use; set `frequency_rank`, `cefr_band`, register.
- Write `en` and `nb` glosses for all 300. LLM drafts allowed; every gloss
  human-edited.
- **Record all 300 with a native speaker**, plus the Unit 1 click minimal-pair
  set. Consent form signed. Process with a first cut of `xh-audio` (or
  `ffmpeg` + `ffmpeg-normalize` as a stand-in — write down what you used).
- Validate `xh-morph`'s first rule set — noun classes 1–10 subject/object/
  possessive concords — against the tutor, as **golden files**. This is
  Rust's first real job.
- Draft Unit 1 (CONTENT.md §8) as static JSON exercises.

**Exit:** 300 lexemes, glossed twice, recorded tier 1, with a golden-tested
concord generator for classes 1–10, and Unit 1 playable from static JSON in
a throwaway Vite page. Operator has done Unit 1 in Norwegian; a friend has
done it in English.

**Kill criterion:** if recording 300 words to standard is not achievable in
~3 weeks of part-time effort, stop and rethink the content strategy before
writing the platform. This is the cheapest possible place to learn that.

## Reorder, 2026-09-03: platform before the tutor session

The operator cannot run the tutor session, fill the goldens or record for
some weeks, and does not want the platform to wait. Phase 0's exit
criterion is unchanged; its *timing* moves. Order from here:

1. **Phase 1 in full**, except the three items that need validated content:
   promoting filled goldens into `xh-morph`, seeding the curated 300 as
   `in_review`, and the exit check that Unit 1 is served as `published`.
   The seed loads the lexicon as `draft` only. The golden test stays red and
   runs in CI as a separate, non-blocking `content-gate` job so the crate is
   visibly unvalidated without blocking code checks.
2. **Editor dashboard content tools** from Phase 3, pulled forward because
   they make the tutor session and the recording weeks cheaper: batch
   recorder, gloss editors, review queue, golden-entry screen.
3. **Learner MVP** (Phase 2) against synthetic fixtures in local and preview
   databases. The learner surface still reads `published` only; real content
   appears the day an editor publishes it.
4. **Then, last:** tutor session, goldens, glosses, recording, publish
   through the real gate, and only then the two-week retention test.

What does not move: nothing unvalidated is published, no golden is filled
by anyone but a tutor, no isiXhosa is generated by a model, and no exit
criterion is declared met early. The Phase 0 kill criterion still applies
when recording starts; the platform work before it is what we would build
anyway.

## Phase 1 — Skeleton

**Goal:** the platform exists, deploys, observes itself, and the agent can
operate it through the CLI.

Parallel workstreams (independent; can be separate agent sessions in
worktrees):

- **A. Monorepo + tooling** — Bun workspaces, Oxlint/Oxfmt, Vitest, Cargo
  workspace, Blacksmith CI with all gates, Docker Compose (Postgres, MinIO,
  Mailpit). the library notes started.
- **B. Data** — `packages/core` status machine + exercise schemas;
  `packages/db` Drizzle schema for ARCHITECTURE §2; migrations; seed from
  Phase 0 output; `test:integrity` suite green.
- **C. API** — Hono on Workers, Better Auth with roles, Hyperdrive to Neon,
  R2 buckets, Queues declared, Sentry wired. Learner read routes; editor
  write routes for lexeme/gloss/audio; publish transition endpoint.
- **D. Rust** — `xh-audio` real (symphonia/ebur128/rubato/opus), manifest
  format frozen; `xh-fsrs` wrapping fsrs-rs with WASM export and a TS smoke
  test; `xh-morph` classes 1–10 promoted from Phase 0 goldens into the crate.
- **E. CLI** — `molo doctor`, `db`, `content ingest|stats|promote`, `audio
  process|missing`, `morph gen`, `cf deploy|tail`, `sentry issues`, dry-run
  by default, `--live`, `--json`.
- **F. Infra** — Alchemy for Workers/R2/Queues/Hyperdrive; preview per PR
  with Neon branch; prod behind protected env.

**Exit:** `molo doctor --json` green against `preview`; Phase 0 content is in
Neon as `published` via the real gate; `GET /units/1` returns Unit 1 with
signed audio URLs; Sentry shows a deliberately thrown error; CI is green on
Blacksmith; `bun run test:integrity` passes and fails correctly when the gate
is sabotaged.

## Phase 2 — Learner MVP (web)

**Goal:** a Norwegian and an English speaker complete Units 1–2 on the web,
with FSRS review and the first gamification loop.

- TanStack Start learner app; i18n en/nb; source-language selection.
- Exercise widgets: `listen_select`, `select_listen`, `translate_tap`,
  `match_pairs`, `click_drill` (listen-and-identify variant only), `culture_card`.
- Session = due cards ∪ new cards; `packages/scheduler` writes `review_log`.
- XP, daily goal, streak, level. No leagues yet. Motion used for feedback,
  sparingly.
- Playwright e2e: complete a lesson; publish gate blocks unpublished
  content from appearing.
- Units 1–2 content complete (≈150 lexemes), tier 1 audio.

**Exit:** two real people, two source languages, Units 1–2, seven consecutive
days of use with streaks intact, review sessions surfacing due cards
correctly. Then **two weeks of use without new features**, because "is this
retaining anything" is a hypothesis that calibrates against real review logs
or not at all.

## Phase 3 — Editor dashboard

**Goal:** content production stops depending on the operator's terminal.

- `/edit/*`: content grid (FTS), lexeme editor with `xh-morph` preview, gloss
  editors per language, in-browser batch recorder, review queue with
  four-eyes, sentence builder, revisions, speaker consent records.
- LLM assist producing `ai_draft` glosses/notes/sentences, visibly badged.
- Forvo backfill consumer (non-profit tier; config flag for commercial).
- Weekly Slack reports.
- Onboard the first external editor (the tutor). Their first week is the
  usability test.

**Exit:** an editor who is not the operator takes a word from `draft` to
`published` — including recording it — without touching a terminal or asking
a question. Units 3–4 authored primarily through the dashboard.

---

## Phase 4 — Mobile

**Goal:** the habit loop lives where habits live.

- Expo SDK 57 learner app; NativeWind; same exercise contracts; audio via
  `expo-audio`; `xh-fsrs` WASM on device; op-sqlite + SQLCipher offline cache
  of published units and `review_cards`.
- Push reminders (opt-in) for streak at risk.
- Maestro flows: onboarding, lesson, review, offline lesson.

**Exit:** a lesson completes in airplane mode and syncs cleanly on
reconnect; store-ready builds via EAS.

## Phase 5 — Depth

Only now, and only what the review logs justify:

- `xh-morph` classes 11–15, verb extensions (applicative, causative,
  reciprocal, passive), tense/aspect morphology → `concord_fill` and
  `translate_type` at A2.
- `speak` exercise with advisory ASR; engine evaluation on editor-labelled
  learner clips (CONTENT.md §6). Consented attempt storage begins.
- Weekly leagues.
- A2 content programme with paid editorial hours.
- fsrs-rs parameter optimisation on real `review_log` data.
